# 路由不依据可用性自动切换账号

设计审查 Q1 决议（选项 A）。多个绑定可能都能访问同一文档，但"能访问"不等于"用户期望以此身份操作"。路由选择操作身份的优先级固定为：本次显式指定 > 文档级 pin（用户此前确认的选择）> 候选集内唯一绑定（sole，按存在性判定）> 首次询问并记 pin。任何环节都禁止"因另一绑定 ready/可用而自动切换写入"；tenantHints 与能力探测结果只作候选展示辅助，永不参与自动选择。

## Considered Options

- A（选定）：显式优先 + pin + 首问，失效不自动换号。
- B：按空间/租户配置默认账号——减少询问，但域名规则覆盖不了分享场景，且仍是"替用户猜身份"。
- C：任意有权限账号皆可，失效即换——操作归属身份不可控，被否决。

## Consequences

- 首次遇到歧义文档会询问一次（可记住）；绑定失效会阻塞该文档操作，直到修复授权或用户明确改选——这是刻意的，不是缺陷。
- "能力 ≠ 意图"是路由层的核心不变量：Q4 的探测、tenantHints、ready 状态都不得成为自动选择依据。
- 实现于 design.md §5 消歧算法（confidence: explicit | pinned | sole | asked）。
